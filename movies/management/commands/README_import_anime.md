# RAFS: импорт аниме

Импортёр написан с помощью ИИ (OpenAI Codex). Он использует текущую модель
`Movie` для фильмов и целых сериалов. Эпизоды и сезоны отдельно не импортируются.
Новые зависимости, модели и миграции не нужны.

## Отбор и подтверждение источников

TMDB Discover вызывается отдельно для `movie` и `tv` с одновременными условиями:

- жанр Animation (`with_genres=16`);
- точное ключевое слово anime (`with_keywords=210024`);
- `include_adult=false`, для movie также `include_video=false`;
- по умолчанию `vote_count.gte=0`. Язык оригинала и страна не являются фильтром.

2026-10-15 реальные последовательные запросы с настроенным TMDB Read Token
подтвердили `/keyword/210024 → {id: 210024, name: "anime"}`. Поиск keyword
также вернул **другие** метки: `222243 based on anime`, `327471 anime inspired`,
`359095 anime live-action`. Они намеренно не включены в отбор.
При запуске точная метка повторно проверяется через API (или сохранённый кеш).
Детали каждого кандидата заново проверяются на наличие Animation и anime:
совпадения одной лишь анимации или японского языка недостаточно.

Проверены реальные ответы `movie/129` (Spirited Away) и `tv/1429` (Attack on
Titan): у movie используются `title`, `release_date`, `keywords.keywords`, у tv
`name`, `first_air_date`, `keywords.results`. Оба источника предоставляют свои
`external_ids` и `translations` через `append_to_response`. Для Wikidata TMDB
movie ID — **P4947**, TMDB TV series ID — **P4983**; IMDb — P345.

Это консервативная выборка, а не импорт «всех существующих аниме». Метки и жанры
TMDB заполняются сообществом: возможны пропуски и неверная разметка. Работы без
метки anime не попадут в список; ошибочная метка тоже возможна. Не включаются
все мультфильмы, экранизации аниме с живыми актёрами или все японские работы.
Успешный импорт дополнительно зависит от доступности и полноты Wikidata.

## Формат произведения и безопасная идентичность

- Кандидаты сопоставляются по Wikidata ID из TMDB либо по точным TMDB/IMDb ID,
  с существующими проверками совпадений в RAFS. При противоречиях или нескольких
  соответствиях запись пропускается. Фиктивные QID не создаются.
- Название и год используются только для остановки возможного дубля без ID.
  По одному названию произведения не объединяются.
- Тип берётся из прямого P31 Wikidata. Через P279 проверяется принадлежность
  к film (Q11424), television series (Q5398426) либо web series (Q526877).
  Для совместимости с TV-источником принимаются и целые web/ONA-сериалы.
  Сезоны (Q3464665), эпизоды (Q21191270), противоречивые, отсутствующие и
  неоднозначные типы пропускаются. Для TV нет подстановки «полнометражный фильм».
- Иерархия ограничена 8 переходами и 256 классами; слишком сложная или неполная
  классификация требует ручного разбора. Отдельные TV specials и OVA, которые
  Wikidata не подтверждает как фильм или целый сериал, могут быть пропущены.
  Жанры берутся отдельно из P136 и не подставляются в `type_of_work`.
- Непустой ручной тип, название, описание, год, переводы, обложки и ID сохраняются.
  Заполняются только пустые поля, существующие связи не удаляются. Сохраняются
  доступные жанры, страны, студии, режиссёры, сценаристы, продюсеры, композиторы,
  актёры и актёры озвучки, подтверждённые Wikidata. `last_synced_at` обновляется.
- Доступные переводы en, ru, uk, kk, es, de записываются в Parler отдельно:
  название/описание из TMDB, при отсутствии — label/description того же языка
  из Wikidata. Отсутствующие переводы не заполняются английским текстом.
- Обложки — существующее поле `cover_url` с TMDB URL размера w500, если он
  доступен. Файлы в MEDIA_ROOT не скачиваются. Локальные обложки сохраняются.
- Пользовательские оценки, отзывы и поисковые индексы не меняются. Команда не
  запускает существующие команды построения индексов.

## Запуск

Нужен существующий `TMDB_READ_TOKEN` (предпочтительно) или `TMDB_API_KEY` в `.env`.
Секрет не передаётся аргументом командной строки, не выводится и не сохраняется
в кеше. Настроенная Django БД должна иметь применённые миграции проекта.

Из корня текущего репозитория, сначала dry-run на **20 кандидатов всего**:

```bash
cd /home/server/apps/Rafs
.venv/bin/python manage.py import_anime --media-type both --limit 20 --dry-run
```

Потом реальный импорт этих 20:

```bash
.venv/bin/python manage.py import_anime --media-type both --limit 20
```

Большой запуск в tmux с тем же состоянием, увеличив лимит:

```bash
tmux new-session -s rafs-anime
cd /home/server/apps/Rafs
.venv/bin/python manage.py import_anime --media-type both --limit 10000
```

Отсоединение от tmux: Ctrl+B, затем D. Возврат: `tmux attach -t rafs-anime`.
20 кандидатов не означают 20 новых записей: часть уже существует или будет
пропущена. Источники чередуются, поэтому небольшая проверка включает movie и tv,
если в каждом есть кандидаты. По умолчанию доступны также ещё не вышедшие работы
и TV без даты первого показа; отсутствующий год не выдумывается.

`--media-type movie` и `--media-type tv` выбирают один источник. `--min-votes 50`
включает порог популярного кинокаталога: он сильно сокращает полноту для новых,
редких и малооценённых аниме. Для изменения источника, порога, языков, сортировки
или БД укажи **новый** `--state-dir`, например:

```bash
.venv/bin/python manage.py import_anime --media-type tv --min-votes 50 --limit 20 --dry-run --state-dir .rafs_import/anime-tv-votes50
```

## Состояние, остановка и ограничения нагрузки

По умолчанию состояние находится в `.rafs_import/anime/` и не затрагивает
`.rafs_import/state.sqlite3` команды `import_popular_movies`. Если передать
старую папку фильмов, команда отклонит её, не изменяя старую БД состояния.

- `state.sqlite3`: кеш, сохранённый список, курсоры страниц и результаты.
  Ключ кандидата — **(media_type, tmdb_id)**, а не только число ID.
- `import_report.csv`: источник, ID, статус, Movie pk и причина пропуска.
  Поля `dry_status` / `dry_reason` показывают последнюю пробную проверку;
  dry-run не помечает кандидата завершённым для реального импорта.
- `run.lock`: ОС-блокировка для данной папки. Дополнительная блокировка в
  `.rafs_import/anime-runs/` защищает разные папки anime на этой машине.
  На PostgreSQL используется общая advisory lock с `import_popular_movies`.

Лимит ограничивает число обрабатываемых кандидатов, включая пропуски, а не число
созданных записей. Discover сохраняет целые страницы, поэтому в состоянии может
быть больше ID, чем текущий лимит. Доступны до 500 страниц TMDB на источник
(обычно 20 работ на страницу): максимум 10000 кандидатов для movie/tv и 20000
для both. Рейтинг меняется во времени: список пополняется новыми страницами с
дедупликацией по составному ключу, но не является полным снимком всего TMDB.

Ctrl+C безопасно прерывает команду. Повтор той же команды продолжает незавершённые
кандидаты, сохраняя уже завершённые. Транзакция одной работы откатывается целиком
при ошибке. Кеширование, курсор и список на каждой странице сохраняются; лимит
можно увеличить с 20 до 10000 без удаления состояния. Dry-run читает Django БД,
но пишет только своё состояние/кеш/отчёт. Блокировки действуют и для dry-run.

Повторная проверка пропусков с обновлением данных источников:

```bash
.venv/bin/python manage.py import_anime --media-type both --limit 10000 --retry-skipped --refresh-cache
```

`--reprocess --refresh-cache` повторно проверяет созданные/обновлённые записи,
продолжая заполнять только пустые поля. `--refresh-cache` сам по себе не сбрасывает
завершённые статусы и не удаляет работы.

Все запросы последовательны. Минимальные интервалы сохранены: TMDB 0.6 с,
Wikidata 1 с, SPARQL 5 с; их можно увеличить соответствующими `--*-delay`.
Используются общий дисковый кеш, Retry-After, повторы 429/5xx с ожиданием,
немедленная остановка при 401/403 и `maxlag=5` для Wikidata Action API.
`--maxlag-wait` задаёт бюджет ожидания одного запроса (по умолчанию 1800 с),
не отключая maxlag. После исчерпания бюджета повтори команду позже.
Ограничения API не обходятся. Продолжительность большого запуска зависит от
источников, полноты кеша и серверных пауз.

## Проверка разработки

TMDB credentials были настроены; проверены живые keyword/discover/details для
movie и tv. Wikidata Action API во время проверки вернул maxlag, поэтому полная
живая цепочка импорта не подтверждена и ограничения не обходились. Реальный
импорт в рабочую Django БД и массовый импорт не запускались.

Автоматические проверки используют фикстуры API и отдельную SQLite test-БД:
типы, идентичность, переводы, dry-run, возобновление, Ctrl+C, откат транзакций,
сохранение ручных полей и оценок, составные ID, блокировки и Retry-After/maxlag.
Сценарий записи на PostgreSQL и Windows-вариант файловой блокировки отдельно
не проверены. Существующий `import_popular_movies` сохраняет прежние значения
по умолчанию и путь состояния; общие функции дополнены необязательными
параметрами для TV и подтверждённого типа.
