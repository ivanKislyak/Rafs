# RAFS: широкий импорт сериалов

`import_series` написан с помощью ИИ (OpenAI Codex). Вся выдача сохраняется в
существующую Movie: новых Django-моделей, полей, миграций и журнала нет.
Общий небольшой слой `movies/services/catalogue_import.py` расширяет runner
`import_animation`, не копирует его: HTTP/cache/retry, точная идентичность,
формат, `import_one`, блокировки, discovery и SQLite остаются общими.
Старые команды, их defaults и форматы состояния сохранены. Уже работающий
CLI-процесс держит загруженный Python-код; эта реализация не останавливает его
и не открывает его состояние на запись. Новые команды нужно запускать после
освобождения общей блокировки, не одновременно с ним.

## Что входит

- Только TMDB `tv`, целые сериалы/мини-сериалы всех стран, языков, каналов,
  платформ и жанров, включая анимацию и аниме. Netflix и Nickelodeon не фильтры.
- По умолчанию `popularity.desc`, `--min-votes 0`; нет обязательных Animation,
  anime keyword, Scripted, провайдера или региональной доступности.
- TMDB `name`, `first_air_date`, `tv/{id}/translations` и `tv/{id}/external_ids`
  (через append_to_response); сопоставление TMDB TV использует Wikidata **P4983**.
- Adult/video, сезоны, эпизоды, персонажи, франшизы и конфликтующие форматы
  отклоняются. Используется прежний полный bounded обход P31/P279
  (64 перехода / 2048 классов), не жанр вместо типа.
- Сохраняется конкретный подтверждённый P31. Уже заполненный type_of_work,
  в частности тип ранее импортированного аниме, не заменяется.
- Только точные Wikidata/IMDb/TMDB соответствия и перенаправления. Без Wikidata
  — `no_wikidata_match`, неоднозначность — `ambiguous_identity`, конфликт —
  `identity_conflict`. Заголовок/год не разрешают слияние; возможный legacy-дубль
  без ID пропускается для ручной проверки. TMDB-only fallback отсутствует.
- Реально доступные переводы en/ru/uk/kk/es/de, постер URL и подтверждённые связи
  (включая озвучивание P725) добавляются через существующий import_one.
  Английский не записывается вместо перевода другого языка. Нет требований
  русского текста, постера или минимального числа голосов. Ручные непустые
  поля, переводы, обложки, связи и оценки RAFS сохраняются; last_synced_at
  обновляется. Отсутствующие у Wikidata связи не выдумываются.

## Полнота и состояние

По умолчанию **нет цели 15000 и искусственного потолка числа новых карточек**:
`--target-new 0` (или отсутствие аргумента) обходит все доступные сохранённые
разделы. Положительный `--target-new N` — необязательная практическая цель новых
Movie за кампанию, в том числе N > 15000. Existing/updated/skipped/dry-run
не считаются новыми. Цель можно увеличить при resume; фильтры менять нельзя.

`--max-candidates N` ограничивает проверки текущего запуска, включая пропуски;
0 — без ограничения. Ещё один запуск разрешает ещё N проверок. Порция до 20
кандидатов может быть предварительно проверена до достижения target посреди
порции; все оставшиеся ID сохраняются pending. Это не оценка ёмкости источника.

Сначала доступный популярный нефильтрованный список с
`include_null_first_air_dates=true`, затем разделы `first_air_date.gte/lte`.
Переполнение 500 страниц делится дальше по непересекающимся включительным
диапазонам до одного дня. Границы по умолчанию 0001-01-01—9999-12-31,
сохраняются в кампании; можно задать --date-from/--date-to. Эти аргументы
ограничивают именно датированные проходы, а не начальный популярный список.
ID страницы и курсор фиксируются атомарно в SQLite; Movie появляются порциями,
не после загрузки всего каталога. Страница 501 никогда не запрашивается.

Недатированные работы за пределами доступного нефильтрованного списка и
переполненный неделимый день могут остаться необнаруженными. Движущийся рейтинг
TMDB не является стабильным снимком: возможны пропуски при изменении страниц.
Дата/языки/точность источников, неполные Wikidata ID и типы дополнительно
ограничивают результат. Порядок проходов не означает глобальной сортировки.

Состояние по умолчанию `.rafs_import/series/`: state.sqlite3 (cache, результаты,
счётчики, составные ключи media_type/tmdb_id, курсоры), run.lock, summary.json,
import_report.csv и discovery_report.csv. Метаданные включают importer/schema,
отпечаток целевой БД и все фильтры. Несовместимый или чужой state-dir отклоняется
до изменения его содержимого. Состояния аниме/анимации/фильмов не используются.

Возобновление — повтор той же команды. `--refresh-cache` обновляет только кеш
своей кампании; `--retry-skipped` повторяет пропуски. Для повторного discovery
после изменения самого каталога источника нужна новая папка: завершённые
разделы автоматически не пересматриваются. Даже в новой папке точные ID
защищают существующие Movie от дублирования.

PostgreSQL и SQLite фиксируются отдельно. Авария между commit Movie и записью
SQLite может занизить created-счётчик: resume найдёт старую Movie, а не создаст
дубль. Поэтому target — практическая цель, не строгий лимит фактических вставок.
Django-журнал для устранения этой погрешности не добавлен.

Финальные статусы: target_reached, candidate_budget_reached, interrupted,
failed, source_exhausted; available_partitions_exhausted означает завершение
доступных проходов при зафиксированном ограничении покрытия. Ни один статус
не обещает абсолютно весь каталог. В summary смотрите created_in_campaign,
run, campaign_state.skips_by_reason (особенно no_wikidata_match),
coverage_limited_partitions и pending_partitions. При отсутствии target поля
target_new/shortfall равны null. summary обновляется на контрольных точках
не реже чем после 60 секунд работы между порциями/страницами; долгий HTTP retry
может задержать следующую запись. CSV выгружаются потоково при завершении.

## Запуск на Ubuntu

Нужны существующие PostgreSQL и TMDB_READ_TOKEN либо TMDB_API_KEY из настроек
окружения/.env. Секрет не передавайте аргументом команды и не публикуйте логи
с содержимым .env. Схема БД в этой задаче не меняется; дополнительных миграций нет.

Все команды ниже запускайте из:

```bash
cd ~/apps/Rafs
source .venv/bin/activate
python manage.py check
```

Проба без записи Django и индекса (локальные cache/discovery/report сохраняются):

```bash
python -u manage.py import_series --dry-run --max-candidates 20 --state-dir .rafs_import/series-probe
```

Ограниченный настоящий запуск с тем же пробным состоянием:

```bash
python -u manage.py import_series --max-candidates 20 --state-dir .rafs_import/series-probe
```

Полный обход до конца доступных разделов; повтор — resume той же кампании:

```bash
python -u manage.py import_series --min-votes 0
```

Или необязательная цель, без потолка 15000:

```bash
python -u manage.py import_series --target-new 20000 --min-votes 0
```

Фоновый полный обход с выводом в терминал, логом и exit code Python:

```bash
tmux new -s rafs-series
cd ~/apps/Rafs
source .venv/bin/activate
mkdir -p .rafs_import/series
set -o pipefail
python -u manage.py import_series --min-votes 0 2>&1 | tee -a .rafs_import/series/run.log
result=${PIPESTATUS[0]}
echo "Importer exit code: $result"
```

Отсоединение: Ctrl+B, затем D. Вернуться: `tmux attach -t rafs-series`.
Остановка: Ctrl+C в этом терминале; также поддержан SIGTERM.
Прогресс и locks сохраняются/освобождаются при управляемой остановке;
после SIGKILL идентичность проверяется при следующем запуске.
Временные сетевые ошибки не превращаются в no_wikidata_match. Используются
последовательные запросы/пакеты, timeout, backoff, Retry-After, maxlag=5
и ограниченный --maxlag-wait. При длительном сбое команда завершается с прогрессом.

Tmux переживает закрытие SSH, но не reboot. После reboot повторите ту же
Python-команду: сохранённая кампания продолжится. Не удаляйте её SQLite.

Из другого SSH-терминала (только чтение своих отчётов):

```bash
tail -f ~/apps/Rafs/.rafs_import/series/run.log
python -m json.tool ~/apps/Rafs/.rafs_import/series/summary.json
```

Все три старых импортёра и обе новые команды используют один PostgreSQL
advisory lock. Он **немедленно отклоняет** конкурирующий запуск, не ставит его
в очередь. Запускайте animation, series и country_movies последовательно,
включая dry-run. Не останавливайте работающий импорт ради пробы новой команды.

## Поиск и реальные примеры

После обычной порции вызывается существующий refresh_movie_documents:
обновляются только затронутые Movie, остальные документы сохраняются.
Языки/ранжирование не меняются: поиск en/ru/es/de, переводы карточек также uk/kk.
Dry-run не индексирует. Авария после commit Movie/SQLite до индексирования
может оставить документ неактуальным; после восстановления и завершения
кампании при необходимости выполните существующую ручную команду:

```bash
python manage.py rebuild_search_index
```

У неё нет дополнительных аргументов для выбора типов: она атомарно пересобирает
все пять типов GlobalSearchIndex. Не запускается автоматически, в dry-run или
перед импортом. При штатном импорте полный rebuild после каждой порции не нужен.

Проверка источников 1 ноября 2026: живой Wikidata API, без записи каталога:

| Произведение | Wikidata | P4983 (TMDB TV) | IMDb | Проверка формата |
| --- | --- | --- | --- | --- |
| Wednesday | Q105553568 | 119051 | tt13443470 | confirmed_format возвращает Q5398426 (целый сериал) |
| The Haunted Hathaways (2013–2015) | Q3563559 | 59268 | tt2535732 | confirmed_format возвращает Q5398426 (целый сериал) |

Это реальные ответы Wikidata, а не значения, угаданные для теста. Поиск по
The Haunted Hathaways также вернул немецкую запись Q29010465 с другими
P4983=81835 и IMDb=tt9673410, а также сезоны: совпадение названия их не объединяет.
Русские labels Wikidata: «Уэнздей» и «Призраки дома Хатэвэй».

В окружении проверки не было токена TMDB. Независимые details/переводы TMDB,
их adult-флаги и точное двустороннее сопоставление без токена не подтверждены;
нет заявления о полностью успешном живом импорте этих двух работ. Специальных
исключений под них в коде нет. Отбор series больше не требует Animation/anime.

Production .env/БД и работающий каталог не проверялись. Нельзя заключить,
отсутствуют ли эти Movie либо они есть, но не находятся по русскому названию.
Владелец может отдельно проверить совпадения по QID/IMDb в админке, переводы
Movie и документ поиска. В существующих тестах обнаружено независимое падение
русского поиска «северноесияние», воспроизводимое и на HEAD до этих изменений;
алгоритм и assertions поиска здесь не менялись.
