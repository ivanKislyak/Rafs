# RAFS: импорт анимации

Импортёр написан с помощью ИИ (OpenAI Codex). `import_animation` — отдельная
management-команда по образцу `import_anime` и `import_popular_movies`.
Она использует существующую `Movie`, Parler, HTTP-клиент, проверки Wikidata
и `import_one`. Новых моделей произведений или Django-журнала нет.
Прогресс, результаты, счётчики и API-кеш находятся в SQLite.

## Отбор и сохранение

- `--media-type movie|tv|both`, по умолчанию `both`. Импортируются самостоятельные
  анимационные фильмы, короткометражки и целые мультсериалы/мини-сериалы.
- TMDB Animation genre `16` проверяется в discovery и повторно в details.
  Не требуется Family, японский язык, определённая страна или русский перевод.
  `--min-votes 0` — по умолчанию; повышение порога уменьшает полноту.
- Adult/video исключаются. Анимация для взрослой аудитории без флага adult допустима.
- Аниме по умолчанию включено. `--exclude-anime` исключает точную метку `210024`
  в discovery и details: `keywords.keywords` у movie, `keywords.results` у tv.
  Отсутствие этой метки не доказывает отсутствие аниме. В обычном режиме
  отсутствие keywords не мешает импорту.
- Формат подтверждает существующий обход P31/P279: до 64 переходов и 2048
  классов. Сезоны, эпизоды, персонажи, франшизы, сборные сущности и конфликт
  movie/tv отклоняются. Конкретный подтверждённый P31 сохраняется в `type_of_work`;
  жанр не подставляется вместо типа.
- Идентичность проверяется по точным Wikidata/IMDb/TMDB ID и перенаправлениям.
  Movie использует P4947, TV — P4983; одинаковые числовые TMDB ID источников
  независимы. Без Wikidata-соответствия карточка не создаётся (`no_wikidata_match`),
  неоднозначность учитывается отдельно. По названию/году ничего не объединяется:
  обнаруженное вероятное совпадение без ID отправляется на ручной разбор.
- Через `import_one` заполняются пустые поля и переводы, добавляются подтверждённые
  связи, включая актёров озвучивания P725. Ручные непустые данные, оценки,
  отзывы, обложки и существующие связи сохраняются. `last_synced_at` обновляется.
- Реально доступные en/ru/uk/kk/es/de берутся из TMDB/Wikidata отдельно для каждого
  языка. Нет машинного перевода или английского текста вместо отсутствующего
  русского/казахского перевода. Отсутствие постера, года или отдельного перевода
  не является причиной пропуска при корректных названии, формате и идентичности.
  Постер хранится URL в `cover_url`; пользовательские media не заменяются.

## Discovery, состояние и практическая цель

Команда сначала обрабатывает доступный нефильтрованный список каждого источника,
затем датированные разделы: `primary_release_date` для movie и `first_air_date`
для tv. Переполненные диапазоны делятся по датам, с непересекающимися
включительными границами и правильным переходом через високосные дни.
Страница 501 не запрашивается. Переполнение одного дня фиксируется в отчёте.

Границы по умолчанию `0001-01-01`–`9999-12-31`, их можно сузить через
`--date-from`/`--date-to`. Они сохраняются вместе с фильтрами, языками,
источниками и отпечатком подключения к БД. Источники чередуются, все ID страницы
и её курсор сохраняются атомарно в SQLite; импорт идёт небольшими порциями,
без предварительной загрузки всего каталога.

Записи без даты ищутся через нефильтрованный проход (TV включает
`include_null_first_air_dates=true`). Не попавшие в доступные 500 страниц
работы без даты могут остаться необнаруженными. Это не полный снимок TMDB
и не глобальная сортировка всех работ по популярности. Классификация источников
и наличие Wikidata дополнительно ограничивают результат.

`--target-new 15000` — **практическая цель**, а не гарантия 15000 карточек.
Счётчик — число результатов `created` в SQLite данной папки состояния.
`existing`, `updated`, пропуски, ошибки и dry-run не считаются новыми.
`updated` означает заполнение полей/переводов Movie или добавление связей;
одна смена `last_synced_at` не считается обогащением.

**PostgreSQL и SQLite фиксируются отдельно.** Если процесс упадёт после
commit Movie, но до записи результата в SQLite, при resume `import_one`
найдёт существующую карточку по идентификаторам и не создаст дубль. При этом
запись будет учтена как существующая/обогащённая, а счётчик новых может оказаться
заниженным. Дополнительной инфраструктуры для исправления этой погрешности нет.
После таких аварий фактически созданных карточек может быть немного больше
указанной цели. Это не строгий лимит фактического числа вставок.

`--max-candidates N` — отдельный предохранитель проверок текущего запуска,
включая пропуски; 0 означает отсутствие предохранителя. Повтор команды разрешает
ещё N проверок, не обнуляя результаты. Target можно повысить в диапазоне 1–15000.
Порция предварительной проверки до 20 объектов может дать больше `examined`,
чем завершённых результатов при остановке посреди порции; оставшиеся ID не теряются.

По умолчанию используется `.rafs_import/animation/`:

- `state.sqlite3` — метаданные, кеш, составная очередь `(media_type, tmdb_id)`,
  результаты и курсоры discovery;
- `summary.json` — периодическая сводка и финальный статус;
- `import_report.csv` / `discovery_report.csv` — потоковые выгрузки при завершении;
- `run.lock` — файловая блокировка. Папку не нужно удалять при resume.

Статусы: `target_reached`, `source_exhausted`, `candidate_budget_reached`,
`interrupted`, `failed`; периодическая сводка может иметь статус `running`.
`source_exhausted` означает конец сохранённых доступных проходов, а не
доказательство полноты TMDB. Смотри `coverage_limited_partitions`, `shortfall`
и `campaign_state.skips_by_reason`, особенно `no_wikidata_match`.
Проба на 40 кандидатах не оценивает полную ёмкость каталога.

## Переход с версии 43f0000

`0047_animation_import_receipt` сохранена в истории. Новая миграция
`0048_remove_animation_import_receipt` удаляет только старую таблицу журнала.
Movie, переводы и связанные объекты не удаляются. Если 0047 ещё не применена,
обычный `migrate` последовательно создаст и удалит служебную таблицу.
Не удаляй 0047 вручную и не используй `--fake`. На других установках состояние
применения миграций может отличаться.

Перед обновлением останови старый процесс animation и сохрани обычную резервную
копию БД/папки состояния. Само обновление кода не останавливает работающий процесс.

Старый SQLite-формат `animation-v1/schema 1` совместим по структуре. При запуске
с теми же БД/фильтрами он обновляется до `animation-v2/schema 2` под блокировкой.
ID, кеш, результаты, UUID кампании и курсоры сохраняются; счётчик берётся из
строк `created` манифеста. Старый Django-журнал не читается и не восстанавливается.
Если в нём был результат, ещё не попавший в SQLite, возможен описанный недосчёт.

Неизвестный, неполный или чужой формат отклоняется до изменения состояния.
Старые папки автоматически не удаляются. При такой ошибке используй новую папку:

```bash
python -u manage.py import_animation --media-type both --target-new 15000 --min-votes 0 --state-dir .rafs_import/animation-v2
```

Даже в новой папке старые Movie не дублируются: действуют те же точные проверки
Wikidata/IMDb. Новый счётчик начинается с нуля и не включает прежние карточки.
Другую выборку или тестовую копию БД тоже запускай с отдельным state-dir.

## Ubuntu: миграция, проба и tmux

Команде нужен PostgreSQL для общих advisory locks и поискового индекса.
Используются существующие `TMDB_READ_TOKEN` либо `TMDB_API_KEY` из `.env`.
Секрет не передаётся аргументом CLI и не выводится в отчёты.

После остановки старого animation-процесса, из `~/apps/Rafs`:

```bash
cd ~/apps/Rafs
source .venv/bin/activate
python manage.py showmigrations movies
python manage.py migrate
python manage.py check
```

Короткая проба без записи в Django, в отдельном состоянии:

```bash
python -u manage.py import_animation --media-type both --target-new 15000 --min-votes 0 --max-candidates 40 --dry-run --state-dir .rafs_import/animation-probe
```

Dry-run пишет только свои кеш/очередь/отчёт, не завершает реальную очередь,
не увеличивает target и не индексирует. Его результаты — `would_create`,
`would_existing`, `would_duplicate`, а не созданные карточки.

При желании первый реальный запуск можно ограничить 40 проверками основного
состояния, чтобы они уже учитывались в основной кампании:

```bash
python -u manage.py import_animation --media-type both --target-new 15000 --min-votes 0 --max-candidates 40
```

Основной запуск / продолжение в tmux:

```bash
tmux new-session -s rafs-animation
cd ~/apps/Rafs
source .venv/bin/activate
mkdir -p logs
set -o pipefail
python -u manage.py import_animation --media-type both --target-new 15000 --min-votes 0 2>&1 | tee -a logs/import-animation.log
animation_codes=("${PIPESTATUS[@]}")
printf 'Python=%s, tee=%s\n' "${animation_codes[0]}" "${animation_codes[1]}"
```

Отсоединение — Ctrl+B, затем D. Возврат — `tmux attach -t rafs-animation`.
После Ctrl+C/SIGTERM или reboot повтори основную команду с той же папкой:
сохранённый прогресс продолжится. tmux переживает закрытие SSH, но не reboot.
SIGINT/SIGTERM откатывают текущую транзакцию Movie, если commit ещё не произошёл;
при SIGKILL действует обычная повторная проверка ID и допустимая погрешность
счётчика. Коды остановки — 130/143.

Контроль из другого терминала:

```bash
cd ~/apps/Rafs
cat .rafs_import/animation/summary.json
tail -n 30 logs/import-animation.log
```

Повтор пропусков после проверки / исправления источников:

```bash
python -u manage.py import_animation --media-type both --target-new 15000 --min-votes 0 --retry-skipped --refresh-cache
```

`--refresh-cache` очищает только кеш данной кампании, не сбрасывая ID, курсоры
и результаты. Паузы, timeout `(15,70)`, последовательные запросы, ограниченные
retry/backoff, Retry-After, `maxlag=5` и бюджет `--maxlag-wait` переиспользуются
из старого импортёра. Конкурирующий импорт отклоняется блокировками сразу,
а не ставится в очередь. Новые зависимости не добавлены.

## Поиск и проверки

После обычной успешной порции обновляются только затронутые Movie через
минимальную `refresh_movie_documents`. Языки индекса прежние: **en/ru/es/de**.
Переводы uk/kk сохраняются в карточках, но расширения поисковых векторов для
этих языков больше нет. Django-журнал и indexed-флаги не используются.

При аварии между сохранением карточки/SQLite и индексацией некоторые документы
могут остаться не обновлены. Resume не обещает восстановление этого этапа для
уже завершённых строк. После прерванного/ошибочного запуска, а также для удаления
старых uk/kk-векторов, если применялась версия 43f0000, выполни отдельно:

```bash
python manage.py rebuild_search_index
```

Эта команда атомарно пересобирает существующий индекс с прежними четырьмя языками.
Она не запускается автоматически перед импортом или в dry-run и не меняет Movie.

Проверки используют mocked HTTP и отдельную PostgreSQL test-БД: создание Movie,
шесть переводов, связи, сохранение ручных данных, отсутствие дублей, resume,
переход SQLite v1, dry-run, разбиение дат/500 страниц, блокировки и старые команды.
Миграция удаления журнала отдельно проверяется с сохранением Movie, переводов,
M2M и отзывов. Живой массовый импорт и миграции production при разработке
не запускались. Полнота каталога и время импорта не обещаются.

Официальные ограничения discovery:
[Movie](https://developer.themoviedb.org/reference/discover-movie),
[TV](https://developer.themoviedb.org/reference/discover-tv),
[ошибки TMDB, код 22](https://developer.themoviedb.org/docs/errors).
Требования атрибуции из README основного импортёра сохраняются.
